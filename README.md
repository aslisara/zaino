# Explore World

AI-powered travel guide: pick a city, get a guide generated by Claude, save favorites and plan trips day by day.

The project has two parts:

- **Backend** (this repository): Spring Boot REST API with JWT authentication, PostgreSQL and an Anthropic (Claude) integration.
- **Mobile / web client** (`app/`): Flutter app that talks to the API. Runs on Android and in the browser.

> Status: work in progress. Backend is complete; the Flutter client currently covers login, trips, stops, AI guide and favorites. World map, country and city screens are next.

## Features

- Register / login with JWT (stateless, BCrypt password hashing)
- AI travel guide per city (Turkish output): overview, must-see places, food, tips
- Favorites: places, food, restaurants and cities, with filtering
- Trip planner: create a trip with N days, add stops, reorder stops within a day or move them to another day, delete stops
- Add a place from the AI guide straight into a trip day

## Tech stack

| Layer | Technology |
|---|---|
| Language / runtime | Java 21 |
| Framework | Spring Boot 4.1 (Web, Validation, Data JPA, Security) |
| Auth | Spring Security, OAuth2 resource server (JWT, HS256), BCrypt |
| Database | PostgreSQL 16, Flyway migrations, `ddl-auto=validate` |
| AI | Anthropic Messages API via Spring `RestClient` |
| Build | Maven |
| Client | Flutter (Dart), Material 3, `http` package |

## Architecture

```
Flutter app  --HTTPS/JSON-->  Spring Boot API  --JPA-->  PostgreSQL
                                   |
                                   +--RestClient-->  Anthropic API
```

Backend packages (`com.exploreworld`): `auth`, `ai`, `favorite`, `trip`, `config`.

Design notes:

- Stateless security: the user id is the JWT subject; every query is scoped to the authenticated user.
- Database schema is versioned with Flyway and validated at startup (no auto-DDL).
- `open-in-view` is disabled; services own the transactions.
- The Anthropic API key is never stored in code or config files; it is read from an environment variable and AI errors are mapped to clean HTTP status codes (`503` not configured, `502` upstream failure).
- Trip stops are renumbered on insert, move and delete so the order within a day is always consistent.

## API overview

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/auth/register` | Create account |
| POST | `/api/auth/login` | Login, returns JWT |
| GET | `/api/me` | Current user |
| POST | `/api/ai` | Generate AI answer / guide from a prompt |
| POST | `/api/favorites` | Add favorite (`type`: PLACE, FOOD, RESTAURANT, CITY) |
| GET | `/api/favorites` | List favorites |
| DELETE | `/api/favorites/{id}` | Remove favorite |
| POST | `/api/trips` | Create trip (`title`, `city`, `country`, `dayCount` 1-30) |
| GET | `/api/trips` | List trips (newest first) |
| GET | `/api/trips/{id}` | Trip with days and stops |
| POST | `/api/trips/{id}/stops` | Add stop to a day |
| PUT | `/api/trips/{id}/stops/{stopId}/move` | Move stop (`dayNumber`, `position`) |
| DELETE | `/api/trips/{id}/stops/{stopId}` | Delete stop |

All endpoints except `/api/auth/**` require `Authorization: Bearer <token>`.

## Running locally

Requirements: Java 21, Maven, Docker, Flutter SDK.

### 1. Database

Start PostgreSQL 16 in Docker (host port 5433) and make sure the database name, user and password match your local `application.properties`.

### 2. Backend

Set the environment variables, then run the app:

```bash
export ANTHROPIC_API_KEY=<your key>     # required for the AI guide
export JWT_SECRET=<long random string>  # use a strong value outside local development
./mvnw spring-boot:run
```

Health check: `http://localhost:8080/actuator/health`

Flyway creates the schema on first start.

### 3. Flutter app

```bash
cd app
flutter pub get
flutter run -d chrome
```

On the Android emulator the app uses `http://10.0.2.2:8080` automatically.

## Security notes

- No secrets in the repository. API keys and the JWT secret come from environment variables.
- Before any deployment: strong `JWT_SECRET`, HTTPS, CORS restricted to the real client origin, remove the development test account.
